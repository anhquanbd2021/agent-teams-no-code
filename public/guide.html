Guide

What "a team of agents" actually needs

Products like Bot Mode for Hermes Desktop make the roster free: each bot is a role card — pinned model, enabled skills, private memory, persona — assembled in a dialog. This lab shows the four decisions the dialog cannot make for you.

Simulation, honest limits. No models are called; the lab models the shape of handoff, isolation, and termination — not any product's internals.

Start here

What this demo proves

Run the pipeline twice: once with a thin handoff (only a message crosses the seam — every packet field dies) and once structured (goal, constraints, evidence, artifacts, done-condition survive). Then try to read another bot's memory, gate a skill the card never enabled, and run a reviewer↔coder loop with and without a done-condition.

The mechanisms

What to watch

01

The handoff contract

A message is a summary the sender chose to write. The packet — goal / constraints / evidence / artifacts / done — is the contract that keeps the next bot from re-doing the work. Thin mode drops all five fields at every seam; structured mode flags any field the sender forgot.

Try it
"Compare both modes" — thin loses 10 fields across two seams; structured loses zero.
02

Scoped memory

Each bot's memory lives inside its profile. The coder cannot read the researcher's findings — it sees only what the handoff delivered. Denials are audited exactly like allows.

Try it
Act as coder, read researcher.findings — denied and logged.
03

Skill gating

The role card is also a least-privilege grant: a bot can only use skills its card enables. The researcher attempting edit-code is denied — the card, not the prompt, is the enforcement.

Try it
"Researcher attempts edit-code" — denied with the reason named.
04

Termination

Bots are polite and indefatigable: without a done-condition, a request-changes loop only stops when the round cap cuts it. Every exchange is billed.

Try it
Run the loop unchecked — cap cuts it; check "done-condition" and it ends at round 2.

Limits

What this demo does not claim

  • No model is ever called — "work" is a stub that writes findings. The lab shows what crosses the seam, not what an LLM does with it.
  • Memory isolation is a property check, not a security boundary — real isolation is whatever the runtime gives you.
  • The handoff packet mirrors the contract idea, not any product's wire format.
  • The loop model is serial turns; real bot-to-bot delivery may be per-invocation with no mid-flight interrupt.
